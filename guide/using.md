# Using AndromedaConsole

## Prerequisites

Run `npm run console -- doctor` at any time to check the prerequisites and the security setup. In the app, *Options → Prerequisites* shows the same table (required tools first, then optional helpers such as Python, ripgrep, fd, jq, ctags, uv and ShellCheck) and can install what is missing after you approve each command. The console never reads the system PATH, only the one it was started with: after installing a program, start the console again from a new terminal. Installed helpers are named in the prompt of the main and of every agent, and the tab shows how often they were used.

## Steps

1. **Open a project.** On the welcome screen pick a folder (Browse opens the Windows folder window). A *project* is one folder; the console keeps its state in `<project>/.andromedaconsole/`. You can open several projects as tabs. New projects can start from a **template** (`generic`, `backend-java`, `frontend-web`, or your own) that sets profiles, rules and commands, detected from `pom.xml`, Gradle or `package.json`; or start from the settings of a project that is already open. A folder that is not a git repository can be initialised, or cloned from an address, in *Options → Git*. A project with no tests can switch them off (*Inhibit the tests for this project*): reports then say "not run", never "passed".
2. **Talk to the main.** The left panel is a normal Claude Code session that knows the console's tools. Describe what you want; the main decides which jobs to start.
3. **Agents appear on the right.** The main starts one agent per job (profile `developer` by default, the shipped `backend`, `frontend` and `dba`, any you add in *Options → Profiles*, plus the read-only `reviewer` and `recovery` that the console starts itself), or you press *new agent* yourself. Four panels fit; more collapse into bars, and *Compact* folds any panel into a bar (*Expand* brings it back). An agent whose work needs another agent's files can be started *after* it (a last resort; the main must say why), and its ticket merges only after the other one. *Options → Git → Try the project branch* prepares a checkout of the project branch per repository, to build and try it. Agents above the active limit wait in a queue and start by themselves. An agent that has ended for good (its ticket merged, its review done) leaves the column by itself and moves to the *Archived (N)* list in the status bar, where you can bring it back, or delete it from the list (one by one, or *Delete all* after asking; its worktree, branch, ticket and report are kept). The *Archive all finished* button in that list clears every closed agent still in the column in one go, after asking.
4. **Answer.** An agent never asks you directly: it asks the main, which shows you the question (and its options) exactly as written with its own dialog, and passes your answer back; with Remote Control on, that dialog is answerable from the Claude app. The *Queue* (bell) button (`Alt+Q`) opens the drawer with what the console itself asks: merge conflicts, budget decisions, the release confirmation and, for reviewer and recovery sessions, their questions.
5. **Review and merge.** When an agent delivers a ticket the console reruns your tests on exactly that commit (long test runs share one queue per machine, one at a time; after the merges settle it also runs the full `release` command once on `project/<name>` and, if that turns red, works out which merged ticket broke it and tells its author or asks you), a read-only reviewer reads the diff, and the main merges approved tickets one at a time into `project/<name>`. Reaching your real `main` takes one confirmation from you; the console then merges and pushes with a one-time token that the repository's pre-push hook checks.

**Voice dictation.** The microphone button in the main's panel header records from your browser microphone, transcribes with Groq Whisper (the audio is sent to Groq; add your key in *Options → Secrets*, it stays on this computer and is never shown again) and, with *Send to main*, types the text into the main's input without pressing Enter: you confirm in the terminal. The text is typed as plain text, so a transcript starting with `/` or `!` is seen by the main as typed.

Keyboard: `Alt+1` main, `Alt+2…9` agents, `Alt+Q` queue, `Alt+L` the read panel (a readable view of an agent's turns), `Alt+←/→` switch projects. Focus never moves on its own: only your clicks and these shortcuts move it. `Esc` closes the Options, new-project and close-project dialogs.
